Single Kotlin/JVM Gradle module (`core/build.gradle`) with no Android dependencies — it is consumed by both `:catroid` (Android) and a planned `:desktop-runtime`. The central contract is the `RuntimeServices` interface in `runtime/RuntimeServices.kt`, exposing filesystem, main-thread posting, GPS, and vibrator capabilities; each concrete platform supplies its own implementation. Every domain feature follows the same two-file pattern: an interface plus a singleton `*ServiceHolder` object that holds a `lateinit var` pointing at the active implementation (see `AudioServiceHolder`, `NetworkServiceHolder`, `NotificationServiceHolder`, `TextServiceHolder`). Domain packages mirror the Android app's layout (`audio/`, `network/`, `notification/`, `text/`, `pocketmusic/note/`, `stage/`, `content/notification/`, `exceptions/`, `util/Logger.kt`) so the shared code can be imported under the same package path as the Android-side implementations. Dependencies are deliberately minimal: Kotlin stdlib, libGDX for cross-platform primitives, XStream for project serialization, and OkHttp/Retrofit for HTTP.
