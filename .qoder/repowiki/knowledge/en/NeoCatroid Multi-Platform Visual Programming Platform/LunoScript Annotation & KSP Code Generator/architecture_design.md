Two sibling Gradle modules with a strict one-way dependency: `lunoscript-annotations` declares only `SOURCE`-retention annotations (`@LunoClass`, `@LunoFunction`, `@LunoProperty`) consumed at compile time, while `lunoscript-processor` depends on it plus KSP/KotlinPoet. The processor is registered via the standard `META-INF/services/com.google.devtools.ksp.processing.SymbolProcessorProvider` file pointing at `LunoScriptProcessorProvider`, which delegates to `LunoScriptProcessor`. During compilation the processor queries symbols annotated with `@LunoFunction` or `@LunoClass`, builds a single `GeneratedLunoRegistry.registerAllNatives(interpreter)` function using KotlinPoet, and emits it into package `org.catrobat.catroid.utils.lunoscript.generated`; class entries are emitted as constructors wrapping `LunoValue.NativeObject(...)`, function entries call `interpreter.defineNative(name, minArgs..maxArgs) { ... }` with type coercion via `asSpecificKotlinType<T>()`. The generated code targets classes in `org.catrobat.catroid.utils.lunoscript` (Interpreter, LunoValue, CallableNativeLunoFunction, LunoRuntimeError), so this module is purely a compile-time code generator with no runtime footprint beyond the produced source.
