Three-layer design:
- Kotlin public API (`com.gaurav.avnc.vnc.VncClient`) owns an `rfbClient` pointer and exposes `configure/connect/processServerMessage/sendKeyEvent/sendPointerEvent/sendCutText/uploadFrameTexture` etc. An `Observer` interface is the only callback surface; all native callbacks route through `@Keep`-annotated private methods on `VncClient`.
- C++ JNI bridge (`native-vnc.cpp`, plus `ClientEx.h`, `Cursor.h`, `Utility.h`) implements `Java_com_gaurav_avnc_vnc_VncClient_*` entry points, caches a global `JniContext` with `JavaVM*` and method IDs, and forwards libvncserver callbacks (`onGetPassword`, `onVerifyServerCertificate`, `onGotXCutText`, `onFinishedFrameBufferUpdate`, …) back into Java.
- Embedded third-party static libraries are built in-tree via the top-level `src/main/cpp/CMakeLists.txt`: wolfssl (compiled as a `STATIC` target with `OPENSSL_ALL` + AES-GCM/TLS extensions), libjpeg-turbo (static `turbojpeg-static`), and libvncserver (via `add_subdirectory(libvncserver)`). The final shared library `native-vnc` links them together plus `log` and `GLESv2`.
- A single-threaded `Messenger` helper serializes all input events onto one executor so the underlying `VncClient` never sees concurrent writes.
Dependency direction: Kotlin → JNI → libvncclient → (wolfssl/libjpeg-turbo); no reverse dependency from native code into Android APIs beyond the thin callback surface.
