Single-Gradle Android application (`build.gradle`) with `flavorDimensions = ["default"]` producing multiple branded variants: `danvex` (default), `catroid`, `createAtSchool`, `embroideryDesigner`, `lunaAndCat`, `phiro`, `pocketCodeBeta`, `mindstorms`, `standalone`, plus two special source sets `runtime` (a minimal runtime-only APK) and `template`/`apkplayer` (an empty template APK used by the in-app APK generator). Each flavor contributes only branding resources and an overriding `FlavoredConstants.java`; shared Java code lives under `src/main/java/org/catrobat/catroid/...`. The build wires CMake native code (`src/main/cpp/CMakeLists.txt`, ONNX Runtime + LLaMA JNI) into `jniLibs/{arm64-v8a,armeabi-v7a,x86_64,x86}`. A custom `copyAndroidNatives` task extracts libGDX `.so`s from Maven natives artifacts into `jniLibs/` before packaging. Per-variant tasks `packageAppClasses*` and `copyPluginLibs*` compile variant classes into `app-classes.jar` and copy Koin/GDX/XStream deps into `assets/`, which are then registered as asset source dirs for that variant only; `merge*Assets` is hooked to depend on the matching flavor's copy/package tasks. `google-services-template.json` is conditionally copied into `src/danvex/google-services.json` and `src/runtime/google-services.json` so Firebase plugins activate only for those flavors; other flavors have their `processGoogleServices` tasks disabled. Room schema migration files live in `schemas/org.catrobat.catroid.db.AppDatabase/`. Test sources split into unit tests (`src/test/` with Robolectric + PowerMock) and instrumented UI tests (`src/androidTest/` with Espresso, screengrab, and a custom `UiTestApplicationRunner`). A separate Eclipse project `catroidBluetoothTestServer/` provides a desktop Bluetooth server used by the bluetooth integration tests.
